# 매칭 교정 Release 반영 — 2026-10-11

사용자가 첨부한 Release SQLite 두 파일을 기준으로 만든 교정입니다. CSV의 사용자 정의 검수 상태를 그대로 임포트하지 않고 실제 테이블의 연결값과 기존 지원 상태로 변환했습니다.

총 CSV 레코드 133,391개 중 742개를 검토하여 작품 연결 교정 591개, 보류 151개로 처리했습니다. 작품 목록: 교정 37개/보류 50개. 자막 파일: 교정 554개/보류 65개. 기존 확정 회차: 36개 보류. 이전 보류 자막 195개 중 130개를 추가 교정했고, 동일 바이트 중복 26개도 추가 교정했습니다. 축약명 38개 및 추가 근거가 필요한 자막 27개는 보류 상태를 유지했습니다. 새 회차 배정은 없습니다.

원본 파일명, ZIP 내부 경로, SHA256, 출처 파일 ID, 원본 회차는 보존했습니다. 자막 바이트나 ZIP 묶음 자체는 변경하지 않았습니다. DB 스키마와 전체 레코드 수를 유지했습니다. 파일별 근거는 추가 교정 JSON과 changes.csv/jsonl에 있습니다. Release DB의 원본 경로, 내부 제목 추출 결과와 작품 메타데이터를 추가로 대조했으며, 실제 자막 본문을 새로 읽거나 외부 근거 URL을 재검증한 결과는 아닙니다.

적용기는 각 DB의 원본 파일 해시와 모든 테이블의 논리적 행 해시를 확인한 뒤 정확한 이전 값과 일치하는 행만 변경합니다. 변경한 행을 거꾸로 되돌려 원본의 모든 테이블 해시가 복원되는지도 검증합니다. 외래키 및 SQLite 무결성 검사도 통과해야 합니다. 기존 보류 기록의 공급자 연결과 파생 링크도 정리하여 옛 연결이 활성 상태로 남지 않게 했습니다.

GitHub Actions는 현재 db-v1 자산이 첨부 원본 해시와 같을 때만 적용합니다. 두 원본 ZIP을 백업 자산으로 저장한 뒤 교체하고 다시 다운로드하여 검증합니다. 교체 중 실패하면 두 원본을 복원하여 확인합니다. 같은 저장소의 월간 DB/Anikoto/분리 작업과 concurrency 그룹을 공유합니다. publication.json의 published_verified 상태가 실제 게시 완료의 기준입니다. 작업 브랜치 업로드만으로 게시 성공을 뜻하지 않습니다.

오늘 streaming-project에서 수정한 ReAnime/Anikoto 자동 영상 매칭 및 연결 실패 화면의 DB 검색 기능은 앱 코드입니다. 이 SQLite 릴리즈에 앱 코드를 넣거나 WalnutPi 서비스를 배포·재시작하지 않습니다. 앙상블 콘테스트(Anissia 2425)의 기존 올바른 작품 연결은 유지했습니다. 운영 사이트의 잘못된 스트림 캐시/자동 검색 문제는 앱 수정 배포가 별도로 필요합니다.
